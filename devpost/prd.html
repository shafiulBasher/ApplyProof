Features & acceptance criteria

Readiness checks · scope › POC Boundary
  • 2 recommendation letters required, 1 uploaded → Action Needed "Two required; only one uploaded"
  • 3-page CV vs. a 2-page limit → Action Needed, "Official limit: 2 pages · Uploaded CV: 3 pages"
  • 620-word letter vs. a 500–800 limit → Passed
  • Eligibility rule clearly met → Passed; clearly not met → Action Needed
  • Ambiguous rule, different grading scale, or a missing fact → Needs Verification, naming the field to fill in
  • Formatting, quality, and deadlines → Needs Verification, with the source quote
  • Page and word counts are measured exactly in code, not by AI
Evidence-linked findings · scope › Unique Kernel
  • Each finding: the requirement, an explanation, the exact guideline quote, and the page number
  • Evidence from the applicant's side where relevant ("Uploaded CV: 3 pages")
  • Every Action Needed finding has a recommended correction
  • No finding without a source quote, and no requirement is ever invented
Fix-first results
  • Order: Action Needed (expanded) → Needs Verification (expanded if it has items) → Passed (collapsed)
  • Each group shows its count, and any group can be expanded or collapsed
  • Overall status: Action Needed if any exist, else Needs Verification, else Passed
  • Not Checked until a check completes successfully; never Passed while a required criterion is unverified
Recheck & What Changed · scope › "oh, that's cool"
  • Rerun after replacing a file or editing applicant info
  • The summary sits at the top: status changes, value changes, issue-count change
  • Never claims an improvement it can't compare
  • A satisfying transition when a finding changes to Passed
Upload & file identification
  • The type is suggested from the filename (CV, motivation letter, transcript, recommendation letter, other), with no AI, and the user confirms it with a dropdown
  • If unsure, it asks the user and doesn't pre-select a guess
  • Several files of the same type are allowed
  • Replace and remove update the list immediately
Applications, extraction & AI disclosure
  • New Application requires a name, and the new card shows Not Checked
  • Each application shows only its own files, info, and results
  • Extraction covers required documents and counts, page and word limits, eligibility, deadlines, and formatting, each with its quote and page
  • Before the first upload, the user is told that only the guideline's text goes to Google's Gemini API at check time, that free-tier data may be used to improve Google's products, and that applicant documents are never sent. Proceed or cancel.

States & what-ifs

Empty, error & persistence states
  • Empty dashboard: explains ApplyProof, with + New Application
  • No guideline: Run is disabled. "Upload an official application guideline first."
  • Unreadable PDF: "We couldn't extract readable text from this PDF. It may be scanned or image-based." The file stays visible for replacing, and nothing is checked from it.
  • Unreadable guideline: treated as missing, so Run stays disabled
  • Checking: progress indicator, no double-run
  • Inputs changed since the check: a clear notice, and the old results are labeled Outdated until rerun
  • Check fails: previous successful results are kept, the error is shown separately, and the Outdated notice stays if inputs changed
  • Persistence: everything survives closing and reopening on the same browser. Clearing browser data removes it, and the user is told so.
  • Can't save (for example a very large file): the user is told clearly. Nothing is lost silently.

Look & feel

"Colorful and memorable on the surface, precise and trustworthy at the core." A premium indie-hacker SaaS look: Inter, bold headings, subtle gradients, custom icons, rounded cards where they help.

Deep navy Electric violet Mint · Passed Amber · Verify Muted red · Action Warm off-white

Avoid: generic AI landing pages, excessive gradients, glassmorphism everywhere, unnecessary animation, cluttered dashboards.

Boundary

Building What the POC must do
  • Dashboard + Single Application Page
  • PDF upload, with types suggested from the filename and confirmed by the user
  • Requirement extraction with quotes and pages
  • Missing-document, page, and word checks; basic eligibility
  • Fix-first evidence-linked findings
  • Recheck + What Changed
  • AI disclosure, empty and error states, persistence on the device
Deferred Implied, but not now
  • Sign-up and login: right after the MVP works
  • Sync and backup across devices: needs accounts
  • Full check history: latest + previous is enough for What Changed
  • Exportable report: not needed to prove the loop
Non-goals Won't do
  • Finding programs or jobs · writing essays · predicting admission
  • Reading eligibility from the CV · judging writing quality
  • Non-PDF uploads and OCR (scanned PDFs get a clear error)

Open questions

None. All four assumptions were confirmed. Build priority: the demo path first: upload → run → 3-page CV flagged → upload the corrected CV → rerun → Action Needed → Passed. Multiple applications and persistence follow, if feasible, without delaying it.
